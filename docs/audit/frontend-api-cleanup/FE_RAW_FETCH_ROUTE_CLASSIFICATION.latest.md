## 1. Methodology

Two static-source passes over `apps/web/src/**`:

1. `rg -n "fetch\(|withApiFetchAuthDefaults|readApi|writeApi|Authorization|Bearer|credentials:|/documents/generated|/forms/runtime|/forms/runtime-contract|pre-export-config|render-docx|convert-pdf|download|file"` →
   catalog of every HTTP call site (raw `fetch` **and** helper-mediated).
2. Cross-reference with backend controller surface
   (`apps/api/src/modules/documents/document-renderer.controller.ts`,
   `apps/api/src/modules/documents/runtime-template-render.controller.ts`,
   `apps/api/src/modules/documents/bm031-direct/bm031-direct.controller.ts`,
   `apps/api/src/modules/contract-platform/contract-platform.controller.ts`)
   to verify route shapes are not invented by the FE.

No source file was mass-migrated in this PR. No backend route was
touched. No DB / Prisma / DOCX mutation.

## 2. Classification buckets

- **`KEEP_EXPLICIT_TOKEN_BRIDGE`** — routes that fetch binary blobs with
  an explicit `Authorization: Bearer <token>` header (e.g. `file-download.ts`).
  These cannot be silently swapped for `readApi` because of `Content-Disposition`
  + `blob`/object-URL semantics. Keep as-is unless the route target changes.
- **`KEEP_RUNTIME_PREVIEW_HELPER`** — `/forms/runtime/*` helpers
  (`runtime-template-preview.ts`, `runtime-template-export.ts`) that
  already use `withApiFetchAuthDefaults` and were the contract during
  PR-D. Keep as-is.
- **`KEEP_GENERATED_FILE_DOWNLOAD_HELPER`** — generated-document binary
  download endpoints (`/documents/generated/:id/files/:fileId/download`,
  `/documents/preview/sample-data`) that are either (a) read through
  `readApi` (JSON), or (b) addressed via `absoluteApiUrl(...)` and pulled
  with `file-download.ts` when the consumer needs a Blob. Keep as-is.
- **`MIGRATE_TO_READ_API_LATER`** — raw `fetch(...)` wrappers that
  duplicate `readApi` (the per-BM `bmXXX-form-inputs-api.ts` files and
  the 50+ `bm-XXX-form-inputs.tsx` flat-form components). They already
  send `credentials: "include"` and an `Authorization: Bearer` is
  **silently dropped** because Clerk provider is not consulted.
  Migration target: centralize to `readApi` from `api-client.ts`.
- **`MIGRATE_TO_WRITE_API_LATER`** — raw `fetch(..., { method: "POST/PUT/PATCH" })`
  that writes business entities (`cases-api.ts`, `documents-review-api.ts`,
  `documents-api.ts`, `imports-api.ts`, `admin-auth-identities-api.ts`).
  These PATCH /cases/* etc. (not generated form-input routes) so the
  PR-F guard correctly leaves them alone. Migration target: a
  `writeApi<T>` helper derived from `readApi`.
- **`UNSUPPORTED_ROUTE_REMOVE`** — frontend-generated PATCH/PUT save
  routes that backend does **not** support. PR-F removed every helper
  that hit one of these; only the seam module
  (`apps/web/src/lib/document-form-api.ts`) and the static guard
  (`document-form-api.generated-form-input-guard.test.ts`) remain.
- **`UNKNOWN_NEEDS_MANUAL_REVIEW`** — route strings that cannot be
  statically verified (template-string concatenation across files,
  runtime-resolved paths).

## 3. Route inventory

> Table column meanings: **route** is the backend path the FE reaches;
> **file** is the FE source; **method** is `GET/POST/PUT/PATCH/DELETE`;
> **helper/raw** distinguishes helper-mediated (`readApi`, `writeApi`,
> `withApiFetchAuthDefaults`, `downloadFile`) from raw `fetch(...)`;
> **auth bridge** is the token-bridge strategy. **Classification** is
> one of the seven buckets above; **next action** is the future-PR
> playbook.

## 4. BM-170 / BM-172 / BM-031 generated save smoke

PR-F2 added a targeted static-source smoke that runs under
`pnpm --filter api exec tsx --test ../web/src/components/documents/pr-f2-generated-save-smoke.test.ts`:

- Imports the supported helper from `document-form-api.ts`.
- Does NOT import/call any of `patchDocumentFormInputs`,
  `replaceDocumentFormInputs`, `patchBm031DirectFormInputs`.
- Routes the save flow through the supported seam
  (`saveDocumentFormInputs` for BM-170/172, `saveBm031DirectFormInputs`
  for BM-031), and cross-validates that the seam itself is wired to the
  correct POST /documents/generated/:id/{form-inputs,bm031-direct-form-inputs}.
- Surfaces a user-visible failure on save error (`setMessage` /
  `setErrorMessage` / `setSaveMessage` with `error instanceof Error ? error.message : …`).
